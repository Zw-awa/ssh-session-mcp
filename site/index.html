Shared PTY for human and agent 面向人类与 Agent 的共享 PTY

SSH MCP server with a real shared terminal. 把 SSH 变成真正可共享的 MCP 终端。

`ssh-session-mcp` is a shared SSH MCP server for Codex, Claude Code, Cursor, and other AI agents. It keeps one persistent PTY alive, adds a browser terminal viewer, tracks who typed what, and makes remote install, debugging, and long-running work safer to operate. `ssh-session-mcp` 是面向 Codex、Claude Code、Cursor 等 AI Agent 的共享 SSH MCP Server。它保留一条持久 PTY，会附带浏览器终端 viewer、输入来源跟踪和会话级状态管理，让远程安装、调试和长任务执行更可控。

Why It Matters 为什么值得看

Most SSH MCP tools run commands, but do not preserve the terminal as a shared runtime. 很多 SSH MCP 工具能执行命令，但保不住“共享终端运行时”。

When installation prompts, long-running deploys, or remote debugging sessions depend on one real PTY, a stateless wrapper forces the user and the AI to guess. This project keeps both sides on the same terminal state. 当安装提示、长时间部署、远程调试依赖一条真实 PTY 时，无状态包装层会迫使用户和 AI 靠猜。这个项目的目标就是让双方看到同一份终端状态。

Core Flow 核心工具流

Keep the normal MCP + SSH loop short and explicit. 把正常的 MCP + SSH 工作流保持得短而明确。

The common path should stay readable: list devices, connect, run commands, inspect state, poll async work, and retry when remote environments are flaky. 常用路径应该足够可读：列设备、建连接、执行命令、看状态、轮询异步任务，以及在远端环境不稳定时重试。

`ssh-quick-connect`Open or reuse the common SSH session and optionally launch the viewer.打开或复用常用 SSH 会话，并可选启动 viewer。
`ssh-run`Execute commands with completion detection and exit-code capture.执行命令，并跟踪完成状态与退出码。
`ssh-status`Inspect runtime state, viewer state, and active sessions.查看运行时状态、viewer 状态和活跃会话。
`ssh-command-status`Poll long-running work instead of guessing when it is done.轮询长任务，而不是猜它什么时候结束。
`ssh-session-diagnostics`Inspect lock state, running command state, warnings, and viewer health.检查锁状态、运行中命令、警告和 viewer 健康度。
`ssh-retry`Retry flaky commands with a first-class backoff policy.用一等重试策略处理易抖动的命令。
Search-Friendly FAQ 可搜索 FAQ

Answer the questions people actually search before they install. 先回答用户在安装前真正会搜索的问题。

What is the difference between SSH Session MCP and a normal SSH wrapper? SSH Session MCP 和普通 SSH 包装层有什么区别？

A normal wrapper executes one command at a time. SSH Session MCP preserves a shared PTY, so the user and AI agent see the same terminal state, prompts, history, and long-running process lifecycle. 普通包装层通常一次执行一条命令。SSH Session MCP 会保留共享 PTY，让用户和 AI Agent 看到同一份终端状态、提示符、历史和长任务生命周期。

How do I install it for Codex or Claude Code? 如何给 Codex 或 Claude Code 安装它？

Use `npx -y ssh-session-mcp --viewerPort=auto` for the lightest path, then register that command as an MCP server in Codex CLI, Claude Code, Cursor, or another MCP client. 最轻量的路径是 `npx -y ssh-session-mcp --viewerPort=auto`，然后把这条命令注册成 Codex CLI、Claude Code、Cursor 或其他 MCP client 的 server。

Where is it useful beyond install demos? 除了安装演示，它还适合哪些场景？

It is useful for embedded Linux boards, remote deployment hosts, AI-assisted ops, ROS or training machines, and any environment where a human must still inspect or override the shell. 它适合嵌入式 Linux 板卡、远程部署机、AI 辅助运维、ROS 或训练机，以及所有需要人工旁观或接管 shell 的环境。
